# Ludo Mela — architecture and contracts

The design is the spec: `design/artboards/project/*.dc.html` (31 boards, open with `design/artboards/preview.html`
or read the HTML — every artboard is static HTML + a small `renderVals()` with its data). **Behaviour follows
the spec boards (B rules, C economy, D motion/build); visuals follow the screen artboards pixel for pixel**
(390×844 pt reference phone). Where two boards disagree, the later screen board wins (e.g. the lobby is the
v3b "Mela ground" layout in `Main.dc.html`; chests are "Mela pots"; "Equipment" is "Collection"; pieces, not pucks).

## Contracts

### Save — `state/save_controller.dart`
* `saveProvider` = `NotifierProvider<SaveController, SaveData>`; `settingsProvider` = `Provider<AppSettings>`.
  Every change goes through a SaveController method, which writes atomically (SaveStore).
* `SaveData { int schema; AppSettings settings; List<ProfileData> profiles; String activeProfileId;
  DeviceState device /* adsRemoved, consent, firstLaunch, playedMatches for ad pacing, lastAd times */ }`.
* `ProfileData` = one family player: id, name, avatar (`AvatarChoice`: animal id or photo file), wallet
  (coins, gems), xp/level, collection (owned items, shards, upgrade levels, selected dice/pieces/board),
  progress (venues best, cup wins/badges, puzzle streak, mela road claimed), daily (gift streak + claim time,
  free coins time, ladder step/day, ad counts/day, wheel spins, missions of the day + points + claims + swap,
  pots slots + timers), stats (`PlayerStats` by mode/seat/bot, dice rolls for fairness, captures, smart moves),
  play log (capped 2000 `PlayRecord`s). `activeProfile` provider; switching profile switches all of it.
* Clock-safe timers: store wall time + monotonic uptime where the spec asks (daily gift); a clock moved back
  pauses the timer.
* Finished matches call **one** method: `recordMatch(MatchRecord r)` → pays out (entry already paid at start via
  `payEntry`), XP, level-ups (Mela Road rewards become claimable), mission progress, pots (a win fills an empty
  slot), stats, play log; returns a `RewardSummary` for the results screen.

### Match session — `features/match/session/match_session.dart`
The match screen only talks to a `MatchSession` (never to `LudoGame` directly):
```dart
abstract class MatchSession {
  MatchConfig get config;
  GameState get state;
  Stream<MatchUpdate> get updates;          // MatchUpdate { GameState state; List<GameEvent> events; TurnClock? clock; }
  bool canControl(Seat seat);               // a local human (pass & play: several)
  Future<void> roll(); Future<void> move(Move m); Future<void> useCard(CardUse c);
  void sendSticker(Seat from, String sticker);
  void setAnimating(bool busy);             // bots/timeouts wait while the screen animates events
  void setPaused(bool paused);              // pause menu freezes timers and bots (local only)
  Future<void> concede();                   // leave match
  void dispose();
}
```
`LocalMatchSession` (bots + local humans; bot think time scaled by game speed; Expert via `Isolate.run`; turn
timer 15 s (20 s pass & play when enabled) → `AutoPlay`; autosave of the running match so it resumes after the
app is killed), `LanHostSession` / `LanGuestSession` (Wi-Fi). The screen plays `events` in order (hop per square,
capture burst, home burst, toasts) and calls `setAnimating(false)` when done.

### Results
Build a `MatchRecord` (mode, venue, seats, placements, my place, coins from chests, turns, duration, rolls,
captures, smart-move rate, race series for the chart, key moments) → `recordMatch` → `context.go(Routes.result)`
with the `RewardSummary`. The break ad (`AdService.maybeShowBreak`) runs when the player *leaves* the result.

### Routes — `core/router/routes.dart`
`/` splash · `/onboarding` · tabs (round dock): `/lobby`, `/friends` (Wi-Fi hub), `/collection`, `/road`,
`/events` (Mela Cup + events) · drill-ins: `/gift`, `/wheel`, `/venues`, `/pass-play`, `/vs`, `/match`,
`/result`, `/report`, `/puzzle`, `/try-on/:item`, `/terms`, `/insights`, `/profile`, `/settings`,
`/lan/host`, `/lan/join`, `/lan/scan`, `/lan/lobby`. Pop-ups shown over the lobby with `showMelaDialog`:
free rewards, missions, game options, mela pot opening, level-up. Android back: tabs → lobby, lobby → "Leave
the mela?" dialog; match → pause menu.

### Ads (docs/ads.md, from board C)
Banner ONLY at the top of match screens (50 pt reserved); none on splash, lobby, menus, rewards, VS, results,
pause or pop-ups. Break ad only after a finished match, at most every 2nd match, ≥ 4 min apart, never in the
first 3 matches or within 2 min of a reward ad, behind a "Quick break" card, never with Remove ads. Rewarded:
opt-in, labelled "Ad", reward only on completion; coin ads 5/day, gem ads 3/day, 30 s apart. G-rated, UMP first.

## Build waves (who owns what)
Wave 1 (parallel): **engine core** (`packages/ludo_engine`), **foundation** (main/app/app_frame, core/storage,
l10n, router, ads, purchases, notifications, domain/save_data + state/save_controller skeleton, tool/sounds +
assets, android/ios config), **design kit + art** (core/theme, core/widgets, core/art, a dev gallery screen).
Wave 2: engine bots/analysis + puzzles/stats · domain economy + save controller · match screen.
Wave 3: lobby/splash/onboarding · rewards · setup/cup/puzzle · collection/road/terms · profile/insights/settings · Wi-Fi.
Wave 4: integration, translations (bn, hi), adversarial reviews, design-fidelity captures vs artboards, release build.
